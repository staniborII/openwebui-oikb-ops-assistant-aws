# Human docs

Use this whenever you write or edit documentation: a README, an ADR, a guide, a reference page, or a paragraph inside one.

Read the surrounding page first. Match its words and sentence length. Change only the lines the task needs.

## Write the point

Say what the reader can do with the sentence. Name the thing, then say what it means.

The ready email is a good example. Its point is that setup has finished and the URL in the mail is the one to send on. A remark that the password stays in a file does not help that reader. Leave it out.

One idea per sentence. Use the words you would say to a colleague who already knows the system and wants the next fact.

## Before you finish

Read the paragraph aloud. If a sentence only introduces the next sentence, delete it. If a word can go and the meaning stays, cut the word.

Do not use filler: delve, leverage, robust, seamless, landscape, unlock, elevate, foster, it's worth noting, importantly, in order to, the fact that.

Do not open with "It's not X" or "This isn't about X." State the thing itself.

Do not add a summary of what you just said. Do not add a heading the page does not already use.
